What I work on

01

Native & systems programming

C and C++ for Windows and Android, written with a bias toward small binaries, explicit memory management and no runtime that isn't earning its place. When the compiler won't produce what I need, I drop into ARM or x86 assembly and write it by hand.

  • C
  • C++
  • C#
  • ARM
  • x86

02

Reverse engineering & instrumentation

Static and dynamic analysis of native binaries: PLT/GOT and import resolution, structure and vtable recovery, function hooking and inline patching with Frida and Dobby. Findings get written down, because a hook without a note is just a future incident.

  • Frida
  • Dobby
  • PLT / GOT
  • PE
  • ELF
  • IDA
03

Rendering & interface

Direct2D, DirectX 11, Dear ImGui and WinUI 3. I build interfaces that hold their frame rate: custom widgets, animation, layout and theming written by hand instead of pulled from a component library that fights back.

  • Direct2D
  • DirectX 11
  • Dear ImGui
  • WinUI 3
  • HLSL
04

Android & tooling

Native modules for arm64-v8a and armeabi-v7a, ADB-driven device workflows and Lua configuration layers. If a task has to happen on two hundred devices, it becomes a script before it becomes a habit.

About

I started writing code in 2019 and have mostly taught myself by breaking things first. My work sits close to the metal: native Windows and Android code, dynamic instrumentation, and the graphics layer that puts a usable interface on top of it.

I care about software that is small, fast and legible — and about documenting the reasoning behind it. A patch that nobody can explain six months later is a bug with good manners.

Outside of that I rebuild interfaces for fun, argue about pointer arithmetic, and keep a growing collection of half-finished rendering experiments.

— Rao Sahil
